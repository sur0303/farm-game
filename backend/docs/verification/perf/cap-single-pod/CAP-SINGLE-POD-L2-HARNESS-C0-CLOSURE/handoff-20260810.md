## 4. Required Metrics 主链接线

### Preflight

Preflight 现在执行：

1. 加载 common + 当前 measured service 的 required metrics；
2. 校验 Required Metrics schema 与 Active Binding；
3. 从 Collector Snapshot 读取实际 logical metric set；
4. 合并 Harness 自己生成的 planned/launched/unsent/completed/rejected/timeout/arrival lag；
5. 任一 required metric 缺失即拒绝启动；
6. 不允许日志估算或 L1 Primitive 替代。

### Runtime

每个 runtime sample 重复 required-set 检查。Collector 声明成功但少一个 logical metric 仍会失败；不能通过
`missing_metrics=[]` 绕过。

Counter 类型保留上一采样值。任何未解释的下降被记录为：

```text
COUNTER_RESET:<logical_metric_name>
```

并自动停止为 `INCONCLUSIVE_OBSERVABILITY`。

### Scrape gap

- 单个可恢复 scrape error 不立即污染最终结论；
- 连续 gap 超过冻结的 5 秒门后自动停止；
- required metric 明确缺失不等待 5 秒，立即 fail-closed。

## 5. Correctness Oracle Completeness

Oracle Adapter 在进程启动时取得 COUNTER_DELTA baseline，并在每次请求中重新抓取真实 loopback Prometheus correctness
source：

- `COUNTER_DELTA`：当前值减运行前 baseline；
- `GAUGE_CURRENT`：读取当前残留；
- counter 下降：`ORACLE_COUNTER_RESET`；
- source/mapping 失败：`ORACLE_SOURCE_FAILED`；
- 非整数、负数、NaN/Inf：`ORACLE_VALUE_INVALID`。

Harness 在 Preflight 和每次 Runtime Snapshot 都验证 15 个 required gates 的全集。缺少任意 gate：

```text
observation_complete=false
error_code=ORACLE_GATE_SET_INCOMPLETE
```

Preflight gate 已非零时禁止启动。Runtime gate 任一非零时，Correctness 具有最高优先级并立即停止新 arrivals。

R1 exact mapping 在：

`deploy/load/cap-single-pod-r1-oracle-adapter.json`

该配置只定义 test-only adapter 合同；底层 correctness exporter 与 Observability Qualification 仍是
`REQUIRED_NOT_QUALIFIED`，本任务没有伪造 PASS。

## 6. Collector Adapter

真实 test-only Collector Adapter 支持：

- loopback Prometheus text scrape；
- label subset 选择；
- Counter/Gauge/Untyped；
- Histogram/Summary sum、count、P50/P95/P99；
- SINGLE/SUM/MAX/MIN 聚合；
- cgroup v2 `cpu.stat/cpu.max/memory.current/memory.max`；
- measured service、Driver、Observer 和 Dependency 分离；
- `/proc/<pid>/fd` FD 计数；
- cgroup CPU/memory limit drift；
- exact identity file SHA-256 drift；
- primary queue items/bytes/age 和 Redis pool wait logical mapping。

Adapter listener 和所有 scrape source 都必须为 credential-free loopback。配置路径必须为绝对路径，cgroup path 不能逃逸
approved root。Adapter 不输出 cgroup 原始路径、PID、endpoint、Secret 或原始业务身份。

Collector 与 Oracle 都提供固定 `/health`，只返回 adapter kind、当前 executable SHA-256 和 exact config SHA-256。
Run Plan 固定两个 health endpoint 及两个 config hash；Preflight 要求 Adapter binary 与当前 Harness binary 完全相同、config hash
与 Plan 完全相同。最终 Environment/Capacity Evidence 只保存这些 Hash，不保存 raw endpoint/config path。

Observer 自身 CPU/RSS 也进入采样；Observer CPU 超过合同门不能被忽略。

当前各服务 production metric 映射尚未做 Observability Qualification，详情见
`observability-adapter-mapping.json`。缺失生产指标继续归原 B2 Writer，本任务不抢写生产指标。

## 7. Open-loop Scheduler

Scheduler 保持：

- monotonic open-loop arrivals；
- ramp 积分和反函数 schedule time；
- planned、launched、scheduled-unsent 分离；
- lag >50ms 直接 unsent；
- 无 catch-up burst；
- bounded inflight；
- completed/rejected/timeout/failed 分离；
- bounded latency/arrival-lag histogram；
- correctness signal 立即 cancel 新 arrivals；
- Driver product error 只允许 allowlisted code。

Runtime stop 增补了冻结合同中的 sustained gates：

- Driver CPU、arrival lag、actual/planned；
- Dependency CPU/memory/error；
- Service CPU/memory/fd/OOM/rejection；
- Host steal/background；
- primary queue positive windows；
- identity、cgroup、clock、restart、namespace immediate drift。

Stop/Verdict/Environment 文件不是只做 Hash：Generic Core 会验证 schema、precedence 和所实现 threshold 与冻结合同一致；
无法支持的合同漂移会在 Plan load 时失败，而不是静默使用旧常量。

## 9. Schema Runner、Run Plan 与 Evidence

新增 Draft 2020-12 runner：

`scripts/perf/cap-single-pod/verify-json-schema.py`

Runner：

- 检查 Schema 自身；
- 使用 FormatChecker；
- 最多输出 50 个 path/validator，不回显 Secret value；
- Schema/Input/Validation 错误均非零退出。

`run-harness` 在执行 Go binary 前依次校验 exact Run Plan 和 Manifest。Manifest Schema 文件本身还必须匹配 Active Binding
中的 SHA-256，不能把 plan 指向临时宽松 Schema。

Run Plan 使用 typed JSON renderer，拒绝：

- partial placeholder；
- 缺失 replacement；
- 多余 replacement；
- 覆盖已存在输出。

模板和配置位于 `deploy/load/cap-single-pod-*`。示例 values 中的 zero hash 和 `/REPLACE/` path 仅用于 schema/renderer
负控；Go Preflight、文件存在性和 binary identity 会拒绝把它当真实运行计划。

Run Evidence 只在结束前写入 actual `started_at/finished_at`，随后生成 Hash Index。失败、过载和 superseded Evidence
不得覆盖。
