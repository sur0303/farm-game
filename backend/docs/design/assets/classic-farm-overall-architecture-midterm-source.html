关键设计原则
P0 只有四个 Deployment；公网默认 CLB/TLS → farm-gate Direct WebSocket。WAF 与 TCONND/gateproxy 均为探针通过后显式启用的外围 Adapter。
只有 PlayerActor 与 FarmActor 两类权威 Actor；Player/Farm 即使 ID 数值相同，也属于独立 Route Domain 和 Shard 空间。
FriendshipDomain 没有 FriendActor：列表按 player_id 做请求局部化，关系写/Permit 按 canonical pair；正确性来自 Tcaplus CAS 与 relation_epoch。
PlayerMail 与 Friendship 只是在 player-svr 共部署；MailEntry 独立存储，附件资产只能由 PlayerActor 提交。
不建立通用 query-svr：Player/Friend Read API 共部署，读投影可独立扩容为 Role，但不能形成新的业务权威。
单农场最多 200 个会话；FarmSubscriptionHub 管订阅、Join 缓冲和按 Gate 扇出，不是 Actor 或业务权威；FarmActor 最终裁决。
Mailbox 保证玩家业务顺序；PersistenceRuntime 按物理记录分 Lane。跨 Lane 不具备原子性，使用 Intent/Order/Receipt 恢复。
权威事实与关键 Outbox 同提交；P0 不依赖 MQ，Direct/MQ 只属于可替换分发通道，故障不得回滚主链。
作物成熟由 trusted_now_ms ≥ mature_at 派生；Header.schedule_state 是调度唯一真值，Scheduler 只提高提醒及时性。
Tlog 不是业务真值：A 级由已提交事实经 ExportSpool 可靠导出；B 级成功取提交事件、失败可采样；C 级有界队列允许受控丢失。
四条硬边界
好友：canonical FriendRelation + relation_epoch + CAS；Permit 不能只信缓存。
导航：Summary 只做候选；批量精确读后推荐，只有 Join 进入 IN_FARM 并取得 JoinConfirmation 才 MarkVisited。
偷菜：AttemptReceipt 保存目标侧结果；Settlement/OperationResult 闭合访客作物、实际罚金和农场主金币。
邮件：客户端只传 mail_id；ClaimPayload 可信读取，资产 + MailClaimReceipt 单次可靠提交。
实线调用：同步入口或权威裁决　｜　事件链：Outbox → Dispatcher → Consumer　｜　投影可落后：不作为权限和资产真值
