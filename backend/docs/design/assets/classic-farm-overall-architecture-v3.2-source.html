关键设计原则
P0 只有四个 Deployment；公网主链固定为 DNS → CLB/TLS → farm-gate，Upgrade、PRE_AUTH、Ticket、Session 和背压都在 farm-gate。
只有 PlayerActor 与 FarmActor 两类权威 Actor；Player/Farm 即使 ID 数值相同，也属于独立 Route Domain 和 Shard 空间。
FriendshipDomain 没有 FriendActor，但 FriendRelation 是 Tcaplus 长期真值；索引、Redis 与 LRU 都只是投影或缓存。
PlayerMail 与 Friendship 只是在 player-svr 共部署；MailEntry 独立存储，附件资产只能由 PlayerActor 提交。
不建立通用 query-svr：Player/Friend Read API 共部署，读投影可独立扩容为 Role，但不能形成新的业务权威。
Presence 只管理同场订阅与广播，不能证明好友权限；Join 与操作分别验证 Permit，FarmActor 最终裁决。
普通软资产可内存成功后异步合并回写；付费、唯一奖励、关键资产和跨 Actor 步骤必须可靠持久化。
权威事实与关键 Outbox 同提交；Direct/MQ 只是分发通道，Consumer 重复、延迟或故障不得回滚主链。
作物成熟由 trusted_now_ms ≥ mature_at 派生；Header.schedule_state 是调度唯一真值，Scheduler 只提高提醒及时性。
Tlog 分三级：A 经独立 Spool 可靠交接；B 成功从已提交事实派生、普通失败可采样；C 展示可受控丢弃。TGLog 不是业务真值。
六条硬边界
接入：一个 Binary Message = 一个 FarmFrame；PRE_AUTH 有硬上限，慢连接只淘汰自己，旧 generation 必须失效。
好友：canonical FriendRelation + relation_epoch + CAS；Permit 不能只信缓存。
导航：Summary 只做候选；具体弹窗批量精确读，点击后仍由 FarmActor 裁决。
偷菜：AttemptReceipt 保存目标侧结果；Settlement/OperationResult 闭合访客作物、实际罚金和农场主金币。
邮件：客户端只传 mail_id；ClaimPayload 可信读取，资产 + MailClaimReceipt 单次可靠提交。
Tlog：来源事件在 ExportRecord 持久化后才 ACK；SDK 入队不算可靠交接，TGLog 故障不阻塞业务。
实线调用：同步入口或权威裁决　｜　事件链：Outbox → Dispatcher → Consumer　｜　投影可落后：不作为权限和资产真值
