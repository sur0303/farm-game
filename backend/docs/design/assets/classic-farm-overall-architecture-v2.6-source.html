关键设计原则
七个逻辑服务是基线部署边界；只有 PlayerActor 与 FarmActor 两种权威 Actor，模块不等于微服务。
Gate 的 ConnectionEventDispatcher 只分派连接事件；不编排 Workflow，也不分派领域事件。
Session、PLAYER Actor、FARM Actor 是三套路由；ID 数值相同也不代表同一 Shard。
普通 Player 软资产内存原子后异步回写；Farm、唯一领取、付费和跨 Actor 步骤必须可靠持久化。
WorkflowRecord 是唯一全局进度；Actor 只保存本地 Receipt / Settlement。
业务事实与关键 Outbox 同提交；Consumer 路由快照在事件创建时冻结，发布/消费独立记账。
Direct/MQ 是环境级固定模式；生产 MQ 故障禁止自动热切 Direct，切换必须走受控 Runbook。
Presence 不是权限；Join 与偷菜/护理分别取得 Permit。
好友页走查询读链；偷菜/护理回到 Social + FarmActor 权威写链。
作物成熟由 mature_at 派生；Scheduler 属于 P1。
偷菜资产语义
访客：仓库增加作物；页面显示作物估值；钱包扣实际罚金。
农场主：钱包增加与访客实际扣款完全相同的金币。
一致性：Farm 先裁决份额；Workflow 依次闭合访客和农场主 PlayerActor。
故障：中途超时返回 PROCESSING，Worker 按同一 ID 恢复，不回滚偷菜事实。
派生：结算完成后再异步更新活动 Feed、红点、任务、提醒和 BI。
